## 1. 브라우저가 AI 서버에 직접 접근하던 구조

**증상**
- nginx 가 `/ai/`, `/static/` 을 AI 서버로 바로 보내고, 프론트 코드에 AI 서버 주소(`VITE_AI_SERVER_URL`)가 박혀 있었다.
- 백엔드 컨테이너는 `network_mode: service:ai` 로 AI 컨테이너의 네트워크를 빌려 쓰고 있었다. 그래서 nginx 의 백엔드 주소가 `ai:8081` 이라는, 이름만 보면 오타 같은 값이었다.

**원인**
- 코드의 `localhost:5000` 하드코딩을 고치지 않고 배포하려고 네트워크를 공유한 임시방편이었다.
- 그 결과 AI 서버가 외부에 노출되고, AI 컨테이너를 재생성하면 백엔드도 같이 재생성해야 했다.

**해결**
- 백엔드를 모든 데이터가 오가는 중심으로 정했다: `브라우저 → nginx → backend → ai, db`.
- 백엔드에 `/static/**` 중계(`AiStaticProxyController`)를 추가했다. 경로 이탈(`..`)은 400 으로 막는다.
- nginx 에서 `/ai/` 를 제거하고 `/static/` 을 백엔드로 보낸다. AI 와 DB 는 호스트에 포트를 열지 않는다.
- 백엔드는 독립 서비스가 되어 `ai:5000` 으로 AI 를 호출한다. AI 주소는 `PYTHON_API_URL`, `ACCAI_BASE_URL` 로 설정한다.

**교훈**: 네트워크 공유 같은 우회는 설정 값의 의미를 왜곡해서(`BACKEND_HOST=ai`), 다음 사람이 "오타"로 보고 고쳐 장애를 낸다. 실제로 이 값을 `backend` 로 고쳤다가 compose 구성과 충돌해 되돌린 적이 있다.

커밋: acc-backend `16d4499`, acc-front `50f0a9f`, acc-ai `993e263`

## 2. AI 이미지 15.8GB → 3.3GB

**증상**: AI 이미지가 15.8GB, 기동 후 메모리 1.3GB, 기동 약 2분. 저가 클라우드 VM 에 올리기 부담스러웠다.

**원인**: 이미지 안을 크기순으로 보니 `nvidia`(CUDA) 4.1GB, `torch` 1.7GB, `paddle` 0.7GB, `triton` 0.5GB 였다. 그런데 이미지·영상 생성은 전부 외부 API(OpenAI, Replicate, Gemini)라 GPU 를 쓰지 않는다. `pyproject.toml` 의 패키지와 코드가 실제로 import 하는 패키지를 비교하니 PaddleOCR, YOLO, CLIP, Streamlit, Selenium, ChromaDB, Vertex AI 등 다수가 쓰이지 않았다.

**해결**
- 코드에서 import 하는 패키지만 남겼다 (271 → 127개).
- 유일한 로컬 모델인 문장 임베딩(MiniLM)을 위해 torch 는 남기되, `pytorch-cpu` 인덱스의 **CPU 전용 빌드**(같은 2.8.0)로 고정했다. torch 외 패키지 버전은 그대로다.
- CLIP 의 setuptools 우회 설치 단계도 사라졌다.

| | 이전 | 이후 |
|---|---|---|
| 이미지 | 15.8GB | 3.3GB |
| 기동 후 메모리 | 1.30GB | 0.89GB |
| 기동 시간 | 약 2분 | 약 35초 |
| API 라우트 | 17 | 17 (동일) |

**교훈**: 의존성 목록은 "설치된 것"이 아니라 "import 되는 것"을 기준으로 관리한다. GPU 가 없는 서버라면 torch 는 CPU 빌드를 명시한다.

커밋: acc-ai `b2a0c1a`

## 3. `YOUTUBE_API_KEY` 가 비면 AI 서버 전체가 죽음

**증상**: 임시 키로 AI 를 띄우자 `DefaultCredentialsError` 로 기동 중에 종료됐다.

**원인**: `get_youtube_trend.py` 가 모듈을 import 하는 시점에 YouTube 클라이언트를 만든다. 키가 없으면 구글 기본 인증(ADC)을 찾다가 예외가 나고, 라우터 import 가 연쇄로 실패한다.

**해결**: 기동 필수 키를 OpenAI, Gemini, Replicate, **YouTube** 4개로 정정해 시작 가이드에 반영했다. (YouTube 키는 무료)

**교훈**: 외부 클라이언트는 import 시점이 아니라 처음 쓸 때 만들어야 한 기능의 설정 누락이 서버 전체 장애로 번지지 않는다. (후속 과제)

## 4. 샘플 기획서 파일명이 깨져 test 계정 자동 입력 실패

**증상**: test 계정으로 업로드 화면에 들어가도 축제명·키워드·테마·기획서가 채워지지 않았다.

**원인**
- 샘플 목록 API 는 정상이었지만 파일 다운로드가 7개 모두 404 였다.
- 디스크의 파일명이 `ýá£7ÝÜî Ùï¦ýûæ...pdf` 처럼 깨져 있었다. Drive 에서 받은 zip 을 Windows 에서 풀 때 한글 파일명 인코딩이 잘못 해석된 것이다. 단순 코드페이지 변환으로는 복원되지 않았다.
- 프론트는 파일을 받은 뒤에 입력값을 채우는 구조라, 파일이 실패하면 글자 항목까지 비었다.

**해결**
- PDF 첫 페이지 텍스트를 읽어(PyMuPDF) 어떤 축제의 파일인지 확인한 뒤, 디스크 파일명을 **영문 id**(`damyang-santa.pdf`)로 바꿨다. 사용자에게 보이는 한글 이름은 `samples.json` 의 `fileName` 에 둔다.
- 프론트는 입력값을 먼저 채우고 파일은 이어서 받는다.

**교훈**: 여러 OS 와 압축 도구를 거치는 파일은 ASCII 파일명을 쓴다. 표시용 이름은 메타데이터로 분리한다.

커밋: acc-front `3dc0f51`, acc-deploy `07eeb8c`

## 5. API 키를 넣었는데 Docker 가 못 읽음

**증상**: 키를 다 넣었다고 했지만 `env/ai.env` 는 비어 있었다.

**원인**: 키를 `acc-ai/.env`(레포 단독 개발용)에 넣었다. Docker 는 배포 레포의 `env/ai.env` 를 읽는다.

**해결**: 설정 파일이 두 곳인 이유를 README 에 정리했다.
- 각 서비스 레포의 `.env` / `application.properties`: 레포를 단독으로 띄워 개발할 때
- `acc-deploy` 의 `.env`, `env/ai.env`: 도커로 함께 띄울 때. 여러 서비스가 같이 쓰는 값(DB 계정, 공개 주소)을 한 곳에서 관리하고, 컨테이너 주소(`ai:5000`)는 compose 가 넣는다

## 6. 지원 종료된 OpenAI 모델 → 분석 결과가 비고 500

**증상**: 기획서 분석 요청이 500. 프론트에는 내용 없는 500 만 왔다.

**원인 (연쇄)**
```
AI: gpt-4-turbo 호출 → OpenAI 404 (model_not_found, 지원 종료)
 → AI 가 예외를 삼키고 빈 분석 결과를 200 으로 응답
 → 백엔드가 제목(title=null)을 DB 에 저장 → NOT NULL 위반 → 500
```
모델 목록 API 에는 `gpt-4-turbo` 가 여전히 보였다. 실제로 짧은 호출을 보내 보고서야 404 를 확인했다.

**해결**: 종료 모델을 쓰던 5곳(기획서 분석, 포스터 스타일 제안, 리포트)을 `config.OPENAI_TEXT_MODEL`(기본 `gpt-4.1-mini`, 환경변수로 변경 가능)로 모았다. 같은 호출 방식(temperature, JSON 응답)을 이미 다른 8곳에서 쓰는 모델이라 그대로 호환된다.

**교훈**
- 모델명은 코드에 흩어 두지 말고 설정 한 곳에 둔다. 모델은 1년이면 바뀐다.
- "목록에 있다"와 "호출된다"는 다르다.
- 실패를 200 으로 숨기면 원인과 먼 곳(DB 제약)에서 터진다. (후속 과제: 실패는 실패로 응답)

커밋: acc-ai `6847248`

## 7. 축제 기간이 오늘 날짜로 저장됨

**증상**: 2023년 5월 축제인데 DB 의 시작일과 종료일이 모두 오늘(2026-10-27)이었다. 이 날짜로 지역 트렌드까지 잘못 계산됐다.

**원인**
- AI 가 `"2023년 5월 19일(금) ~ 5월 21일(일), 3일간"` 으로 답했다.
- 백엔드 파서는 `yyyy.MM.dd` 만 읽어 실패했고, 실패하면 오늘 날짜로 대체했다.
- 예전 모델은 우연히 `2023.05.19` 처럼 답해서 드러나지 않았다. 모델을 바꾸자 바로 터졌다.

**해결 (양쪽 모두)**
- AI 프롬프트: 반드시 `YYYY.MM.DD ~ YYYY.MM.DD` 로 답하라고 지시
- 백엔드 파서 재작성: `2023년 5월 19일`, `2023-05-19`, `’21.10.1.`, 종료일 연도 생략, 해를 넘기는 기간(`12.28 ~ 1.3`)까지 정규식으로 처리. 12개 사례로 검증

## 15. 이어서 하기 후 선택 화면이 멈춤

**원인**

- 목록 API 는 `pNo` 를 받으면 소유권 검사 후 그 프로젝트를 조회한다. 프론트는 현재 프로젝트 번호를 보낸다.

## 16. 진행 상태 저장이 브라우저에서만 400

**증상**: 실제 화면에서 분석을 진행하자 `PUT /api/progress/{pNo}` 가 400. API 를 curl 로 검증할 때는 정상이었다.

**원인**: 프론트 공용 axios 인터셉터(`BaseAPI`)가 예전 API 호환용으로 **모든 JSON 요청 본문에 `m_no` 를 붙인다.** 백엔드의 커스텀 `ObjectMapper` 는 모르는 필드가 오면 실패하는 기본 설정이라 `Unrecognized field "m_no"` 로 거부했다. curl 요청에는 이 필드가 없어서 검증에서 드러나지 않았다.

**해결**: 요청 DTO 에 `@JsonIgnoreProperties(ignoreUnknown = true)`. 실패한 변경은 프론트 스토어가 들고 있다가 다음 저장 때 다시 보내므로, 서버 수정 후 화면을 이동하자 그동안의 값이 한꺼번에 저장됐다.

**교훈**: API 를 검증할 때는 실제 클라이언트(공용 인터셉터 포함)를 거친 요청으로도 확인한다. 저장 실패 시 재전송 설계 덕분에 데이터 유실은 없었다.

## 17. 이미지 모델의 NSFW 오탐 한 장 때문에 마스코트 4장 전체 실패

**증상**: 마스코트 생성이 `IMAGE_PIPELINE_FAILED` 로 500.

**원인**
| 장 | 모델 (스타일 유사도로 자동 선택) | 결과 |
|---|---|---|
| 1, 2 | recraft | 성공 |
| 3 | sd3 | 성공 |
| 4 (꽃 장식 토끼) | flux | `All generated images contained NSFW content` |

- Replicate flux 의 안전 필터가 평범한 마스코트를 **유해 콘텐츠로 오탐**했다.
- 생성 루프가 한 장만 실패해도 즉시 전체를 실패 처리(fail fast)해, **이미 비용을 낸 3장도 버려졌다.**
- 남은 3장은 AI 폴더에 남았다. 백엔드는 이 폴더의 잔여 이미지를 "생성 후 저장에 실패한 결과"로 보고 재사용하므로(4장 이상일 때), 다음 생성 결과와 **섞일 수 있었다.**

**해결**
- 실패한 장은 다른 모델(recraft → sd3)로 재시도한다. 파이프라인에 모델을 지정하는 인자(`model`)를 추가했다.
- 재시도까지 실패하면 이번 요청에서 만든 파일을 모두 지우고 실패를 반환한다.
- 이미 남아 있던 3장은 수동으로 정리했다.

**교훈**
- 외부 생성 API 는 내용과 무관하게 실패할 수 있다(안전 필터 오탐, 일시 장애). 여러 장을 만드는 작업은 **장 단위 재시도와 대체 경로**가 필요하다.
- "실패 시 재사용"용 임시 폴더는 **실패한 요청의 잔여물을 반드시 정리**해야 한다. 프로젝트 구분 없이 폴더만 보는 재사용 로직은 근본적으로 위험해서, 백그라운드 작업 전환 시 작업 ID 단위로 바꿀 예정이다.

## 18. 파생물 생성 시 참조 이미지 경로가 두 번 겹침

**증상**: 파생 만들기 → 에디터 빌드가 500. 로고 일러스트는 생성됐고 카드뉴스에서 실패했다.

**원인**
```
받은 경로:  /data/acc-front/public/data/promotion/M000001/2/poster/poster_..._2.png  (프론트가 보낸 절대 경로)
찾은 경로:  /data/acc-front/public/data/acc-front/public/data/promotion/...          (public 뒤에 한 번 더 붙임)
```
카드뉴스·리플렛·영상 모듈이 같은 경로 함수를 복사해서 쓰고 있었다. 이 함수는 받은 경로의 맨 앞 `/` 만 떼고 무조건 `FRONT_PROJECT_ROOT/public` 뒤에 붙였다. 로고 모듈은 절대 경로를 따로 처리하고 있어서 같은 입력으로도 성공했다.

**해결**: 네 모듈 모두 "이미 존재하는 절대 경로면 그대로 사용"을 먼저 확인한다. 절대 경로와 상대 경로(`/data/promotion/...`) 둘 다 실제 파일을 찾는 것을 컨테이너 안에서 확인했다.

**교훈**: 같은 경로 처리 함수가 모듈마다 복사되어 있으면 한 곳만 고쳐지고 나머지는 남는다. 공용 유틸로 모아야 한다. (후속 과제)

## 19. 생성 화면 UI: 파생물 선택이 안 보이고, 골라도 반영되지 않음

**증상**: 이미지를 클릭하면 나오는 파생물 선택이 화면 아래로 밀려 보이지 않았다.

**원인 (세 가지가 겹침)**
1. 선택 드롭다운이 확대 모달 안, 화면 높이 85% 이미지 **아래에** 있어서 아래로 열리면 화면 밖으로 나갔다.
2. 그 드롭다운 값은 **어디에도 전달되지 않았다.** "파생 만들기"는 처음 유형 선택 화면의 값만 썼다. 선택지도 포스터 계열 6개로 고정돼 마스코트 화면에도 같은 목록이 나왔다.
3. 생성 화면 레이아웃이 본문 높이를 `calc(100vh - 112px)` 로 잡으면서 위아래 여백 64px 를 빼지 않아 페이지가 넘쳐 스크롤됐고, 맨 아래 버튼이 잘렸다. 프롬프트 패널도 높이를 `calc(100vh - 88px)` 로 따로 잡고 있었다.

**해결**
- 파생물 선택을 상세 화면 **오른쪽 고정 패널**(`DerivativePicker`)로 옮겼다. 프로젝트 `types`(서버 진행 상태)를 직접 읽고 써서 파생 만들기에 그대로 반영되고, 화면별(포스터/마스코트) 선택지를 보여 준다. 영상은 "준비 중"으로 비활성.
- 레이아웃을 `h-screen` 으로 고정하고, 모든 패널이 높이를 따로 계산하지 않고 **같은 부모 높이를 채우게** 해서 위아래 선을 맞췄다.
- 프롬프트 패널은 원문 박스와 입력창의 중복을 없애고, "작성 팁 + 미리 작성된 프롬프트 입력창" 하나로 정리했다.

**교훈**: 화면마다 `calc(100vh - N)` 으로 높이를 따로 계산하면 하나만 바뀌어도 어긋난다. 높이는 레이아웃 한 곳에서 정하고 자식은 채우기만 한다.

## 20. 글자 지우기(ClipDrop) 대체

**증상**: 파생물은 모두 생성됐지만 에디터 빌드 마지막 단계에서 `CLIPDROP_API_KEY 비어있음` 으로 500. 에디터에 들어갈 수 없었다.

**배경**: 에디터는 생성 이미지에서 글자를 지운 배경 위에 수정 가능한 글자를 다시 올린다. 글자 지우기를 ClipDrop 에 맡겼는데 무료 제공이 끝났다.

**해결 1 — 분기**: `CLIPDROP_API_KEY` 가 있으면 ClipDrop, 없으면 Replicate 의 지시형 이미지 편집 모델(`google/nano-banana`, 이미 쓰는 `REPLICATE_API_TOKEN` 재사용). 원본 비율로 출력하고 해상도가 다르면 원본 크기로 맞춘다. 에디터가 원본 좌표에 글자를 다시 올리기 때문이다.

**실측에서 드러난 문제**: 실제 가로등 현수막으로 돌려 보니(13.5초) 원본에 **글자가 없었는데도** 모델이 위쪽 벚꽃 가지를 통째로 지웠다. 지시형 편집 모델은 "나머지는 그대로"라는 지시를 완전히 지키지 않고, 지울 대상이 없으면 다른 요소를 "정리"한다. 출력 해상도도 낮아(576×1792) 키우면서 약간 흐려졌다.

**해결 2 — 글자가 있을 때만 편집**: 저렴한 비전 모델(`gpt-4.1-mini`, 이미지 768px·low detail)에 글자 유무만 먼저 묻고, 없으면 원본을 그대로 쓴다. 글자 없는 현수막은 `no`, 제목이 있는 포스터는 `yes` 로 판별되는 것을 확인했다. 판별이 실패하면 기존처럼 지우기를 시도한다.

**해결 3 — 모델 비교 후 교체**: 같은 두 장(글자 있는 포스터 1792×2400, 글자 없는 1:3 현수막 1024×3072)으로 비교했다. 지원 비율·마스크 등은 문서에 다 나오지 않아 실측으로 확인했다.

| | Replicate nano-banana | **gpt-image-2.5-flare (채택)** | gpt-image-2.5-sunburst | Gemini 직접 |
|---|---|---|---|---|
| 포스터 글자 제거 | O | O | O | — |
| 글자 외 요소 유지 | X (현수막 벚꽃 가지 삭제) | O | O | — |
| 원본 비율 (1:3 포함) | O | O | O | — |
| 출력 해상도 (포스터) | 864×1184 | 1084×1451 | 1084×1451 | — |
| 시간 (포스터 / 현수막) | 17.5 / 13.5초 | 20.2 / 15.2초 | 22.7 / 18.6초 | — |
| 장당 비용 | 약 $0.039 | 약 $0.02 | 약 $0.02 | 무료 등급 키 429 (결제 필요) |

flare 와 sunburst 는 결과를 눈으로 구분할 수 없어, 같은 가격에 빠른 flare 를 기본값으로 정했다. 실패하면 Replicate 로 대체한다. 이후 실제 흐름에서 에디터 빌드가 처음으로 끝까지 성공(200)했다.

**남은 한계와 교훈**
- 지시형 편집은 원리상 그림 전체를 다시 만든다. 모델에 따라 "나머지 유지" 정도가 크게 달라서, **문서 대신 같은 입력으로 실측 비교**해야 고를 수 있다.
- 제공자·모델을 설정(`TEXT_REMOVAL_PROVIDER`, `TEXT_REMOVAL_MODEL`)으로 빼 두면, 더 나은 모델이 나와도 코드 수정 없이 바꿀 수 있다.
- 최고 품질은 여전히 **글자 위치만 메우는 마스크 방식**이다. (후속 과제)
- 생성형 모델로 "결정적인 편집"을 대체할 때는 **입력에 따라 하지 않아도 될 일을 하지 않게** 하는 가드가 필요하다.

## 21. 에디터 템플릿을 백엔드가 못 읽음 (컨테이너 경로)

**증상**: 에디터 빌드가 처음으로 성공한 직후, 에디터 화면이 "템플릿 데이터 가져오는 중 오류"로 튕겼다. `GET /api/editor/project/{pNo}/template-json` 500.

**원인**
```
AI 컨테이너:     /app/app/data/editor/2/layout/total.json 에 템플릿을 만들고 이 경로를 DB 에 저장
백엔드 컨테이너: 같은 경로를 Files.readString → 백엔드에는 AI 데이터 폴더가 없음 → NoSuchFileException
```
같은 PC 에서 두 서버를 띄우던 시절에는 경로가 우연히 맞았다. 컨테이너를 나누자 **"파일 경로를 서비스 간에 주고받는" 설계**가 드러났다.

**해결**: 백엔드는 같은 디스크에 파일이 있으면 직접 읽고, 없으면 AI 서버의 정적 경로(`/static/editor/...`)로 HTTP 조회한다. 백엔드에 AI 데이터 폴더를 마운트하는 방법도 있었지만, "백엔드가 AI 를 호출하는 중심" 구조에 맞고 서버를 나눠도 동작하는 HTTP 방식을 택했다.

**교훈**: 서비스 간에는 파일 경로가 아니라 **식별자나 URL** 을 주고받아야 한다. 경로는 그 경로를 만든 프로세스의 파일시스템에서만 의미가 있다. (남은 곳: 백엔드가 AI 결과를 공유 볼륨 경로로 옮기는 흐름 → #30)

## 22. 에디터에서 파생물 이미지가 안 보임

**증상**: 에디터에 들어가자 가로등 현수막만 보이고 로고·카드뉴스·표지판·키링은 비어 보였다.

**원인 (세 가지가 겹침)**
| | 가로등 현수막 (보임) | 로고·표지판·키링 등 (안 보임) |
|---|---|---|
| 이미지 주소 | 웹 주소 `…/static/editor/…` | 컨테이너 파일 경로 `/data/acc-front/public/data/…` |
| 캔버스 크기 | 원본 픽셀 크기 | 없음 → 800×450 가로 캔버스에 작게 |
| 썸네일 | 배경 이미지로 생성 | 배경이 없어 비어 있음 |
| 파일 형식 | PNG | **이름은 `.png`, 내용은 JPEG** |

파생물 모듈 다섯 개가 저장한 파일 경로를 그대로 돌려줬고, 이미지 생성 API 가 준 JPEG 를 확장자만 `.png` 로 저장하고 있었다.

**해결**
- AI 가 파생물을 템플릿에 넣는 **한 곳**(`append_extra_items_to_total`)에서 정리한다: 웹 경로로 변환, 이미지 실제 크기로 캔버스 설정, 형식이 다르면 진짜 PNG 로 다시 저장. 모듈 다섯 개를 각각 고치지 않아도 된다.
- 에디터는 배경이 없으면 첫 이미지 객체로 썸네일을 만든다.
- 이미 만든 프로젝트의 템플릿에도 같은 정리를 적용해 **재생성 비용 없이** 복구했다.

**교훈**: 여러 생성 모듈의 출력이 제각각일 때는 각 모듈을 고치기보다 **소비 직전 한 곳에서 정규화**하는 편이 빠르고 빠짐이 없다. 확장자는 형식을 보장하지 않는다. 파일 헤더(매직 바이트)로 확인한다.

## 23. 재시도할 때마다 베이스 이미지가 중복으로 쌓임

**증상**: 파생 만들기가 실패해 다시 시도할 때마다 같은 베이스 포스터·마스코트가 프로젝트(마이페이지)에 계속 늘어났다.

**원인**: 파생 만들기는 먼저 베이스 포스터·마스코트를 `promotion_path` 에 저장한 뒤 에디터 빌드를 한다. 저장이 매번 `INSERT` 라, 빌드가 실패해 다시 누르면 같은 행이 또 들어갔다. 2번 프로젝트에서 세 번 시도해 베이스 행이 6개였다.

**해결**: 프로젝트마다 홍보물 유형별 한 행으로 정했다.
- V5 마이그레이션: 기존 중복은 유형별 최신 행만 남기고, `(p_no, db_file_type)` 유니크 제약을 건다.
- 저장 SQL 을 `ON DUPLICATE KEY UPDATE` 로 바꿔 같은 유형을 다시 저장하면 경로를 교체한다. 베이스를 바꿔 다시 시도하면 최신 선택으로 바뀐다.
- 베이스 저장과 파생물 저장 두 경로가 같은 SQL 을 써서, 코드 두 곳을 각각 고치지 않고 DB 규칙 하나로 해결했다.

**교훈**: 재시도가 가능한 작업은 **멱등**(여러 번 해도 결과가 같음)해야 한다. 애플리케이션 코드보다 DB 제약으로 보장하면 새 저장 경로가 생겨도 지켜진다.

## 24. 지역 트렌드가 가짜 데이터를 실제처럼 보여 줌

**증상**: 지역 트렌드 그래프가 그럴듯해 보였지만, 축제 검색량 정점이 **날짜 버그로 잘못 저장된 축제일(2026-10-27)과 정확히 같았다.** 실제 검색 데이터라면 잘못된 날짜를 알 수 없으므로, 지어낸 데이터였다.

**원인 (다섯 가지가 겹침)**
| | 문제 |
|---|---|
| 검색어 | 사용자 키워드 JSON 배열 문자열(`["태화강", "국가정원", …]`)이 **통째로** 네이버 검색어로 들어감 → 검색량 거의 0 |
| 지역 | 지역 이름을 기획서 '주최' 칸에서 그대로 사용 → 주최가 `정보 없음`이라 "정보 없음 여행"을 검색 |
| 기간 | 항상 오늘 기준 1년 → 2023년 축제를 2025~2026 검색량으로 분석 |
| 대체 | 실패하거나 검색량이 적으면 **축제일에 정점을 찍는 무작위 곡선**을 만들어 `success` 로 반환. 키워드별 미니 그래프는 항상 무작위 |
| 전달 | 백엔드 DTO 가 정의하지 않은 필드를 버려, 성장률·구글·유튜브 결과가 화면에 도달하지 못함 (성장률 카드는 한 번도 표시된 적 없음) |

**해결**
- 검색어: 개별 키워드 + 연도·회차를 뺀 축제명 (`trend_inputs.festival_terms`)
- 지역: 주최가 비었거나 기관명이면 축제명·장소로 시·군 이름 추정 (`resolve_region_name`, 경량 모델)
- 기간: 지난 축제면 축제 시점 기준 1년 (`search_window`)
- 예시 곡선을 쓰면 `region_trend_simulated` 와 이유를 반환하고 성장률은 계산하지 않음. 화면에 "예시 데이터" 배지와 안내, 분석 지역·조회 기간 표시
- 백엔드 DTO 에 `@JsonAnySetter/@JsonAnyGetter` 를 달아 AI 응답 필드를 그대로 전달

**결과 (태화강 같은 입력으로 재분석)**
| | 이전 | 이후 |
|---|---|---|
| 지역 | 정보 없음 | 울산 |
| 조회 기간 | 2025-11 ~ 2026-10 | 2022-07 ~ 2023-07 |
| 그래프 | 예시 곡선 (가짜) | 실제 네이버 검색량 |
| 성장률 | 화면에 안 보임 | 축제 +282%, 지역 +94% |
| 구글 / 유튜브 | 0건 / "정보 없음 여행" | 53건 / "울산 여행" 5건 |

**교훈**
- **"실패하면 그럴듯한 값으로 채우기"는 버그를 숨긴다.** 대체 데이터를 쓸 거면 반드시 그 사실을 함께 돌려주고 화면에 드러내야 한다. 분석 서비스에서 이건 신뢰의 문제다.
- 결과가 그럴듯해도 **입력(실제 검색어·기간)을 로그와 응답에 남겨야** 검증할 수 있다.
- 계층 사이 DTO 가 필드를 조용히 버리면, 아래에서 만든 기능이 화면까지 도달하지 못한다.

## 25. 파생물 이미지가 배경에도 깔림 (#22 의 회귀)

**증상**: 에디터에서 로고·표지판 같은 파생물 이미지를 드래그하자 뒤에 같은 그림이 배경으로 남아 있었다.

**원인**: #22 에서 배경이 없는 파생물의 **썸네일**을 첫 이미지 객체로 만들도록 바꿨다. 그런데 캔버스 로더는 배경을 `backgroundImageUrl || thumbnailUrl` 로 정하고 있어서, 썸네일이 배경으로도 쓰였다. 같은 값이 "목록 표시용"과 "배경 대체값" 두 용도로 쓰인다는 걸 확인하지 않았다.

**해결**: 배경은 `backgroundImageUrl` 만 쓴다. 썸네일은 목록 표시에만 쓴다.

**교훈**: 값을 바꿀 때는 **그 값을 읽는 모든 곳**을 검색해 확인한다. 하나의 필드에 두 가지 의미를 싣지 않는다.

이 과정에서 에디터가 **자동 저장이 없고, 저장해도 완성 PNG 만 남겨** 편집 상태가 다시 열면 사라진다는 점도 드러났다. 실제로 4번 프로젝트에서 파생물 편집 후 서버에 들어온 저장 요청은 0건이었다.

**추가 해결 — 자동 저장과 편집 상태 복원**
- 캔버스 변경 후 2초 / 디자인 전환 / '최종' 이동 전에 자동 저장한다. 편집 상태(캔버스 JSON)는 서버 진행 상태에, 완성 이미지는 프로젝트(유형별 교체, V5)에 저장한다.
- 다시 열면 편집 상태로 복원한다. 원본 템플릿 식별값(sourceKey)이 다르면(베이스를 바꿔 다시 생성) 예전 편집은 적용하지 않는다.
- 상단바에 저장 상태를 표시하고, 저장 전에 창을 닫으면 경고한다.

## 26. 다른 프로젝트를 이어서 해도 포스터가 "가장 최근 프로젝트"로 생성됨

**증상**: 포스터·마스코트 생성을 백그라운드 작업으로 옮기면서 생성 서비스를 살펴보니, 프로젝트 번호를 받지 않고 있었다.

**원인**: 생성 서비스가 프로젝트를 `회원의 가장 최근 프로젝트`로 정했고, 기획서 요약도 로그인 정보(`CurrentMember`)로 "최신 프로젝트"를 찾아 읽었다. 그래서
- 예전 프로젝트를 "이어서 하기"로 열고 생성하면 **최근 프로젝트에 생성**되거나 **다른 기획서 요약**이 쓰일 수 있었다.
- 요청이 없는 작업 스레드에서는 로그인 정보가 없어 그대로는 실패한다.

**해결**: 생성 서비스가 프로젝트 번호를 직접 받는다(기존 메서드는 그대로 두고 번호를 받는 메서드를 추가). 기획서 요약은 그 프로젝트 번호로 조회한다. 파일은 프로젝트 소유자 폴더에 저장한다(관리자가 대신 실행해도 소유자 것).

**교훈**: "현재 사용자", "최근 항목" 같은 암묵적인 문맥은 요청 스레드 밖으로 나가는 순간 사라지거나 틀린다. 작업에 필요한 식별자는 명시적으로 넘긴다.

## 27. 공개 배포 전 점검: 회원번호·서버 경로·내부 주소가 브라우저에 노출

**증상**: 홍보 패키지 화면의 파일 목록에 `/data/promotion/M000011/5/poster/poster_….png` 같은 서버 경로가 그대로 보였다. 전체를 점검해 보니 다음이 함께 드러났다.

| 노출 | 위험 |
|---|---|
| `/data/promotion/{회원}/{프로젝트}/...` 이미지가 **로그인 없이** 열림 | 번호만 바꿔 남의 결과물을 열 수 있음 |
| `/static/editor/projects/{pNo}.json` 공개 | 서버 절대경로·회원번호, 프로젝트 번호로 열거 가능 |
| `/static/*.csv`, `/poster-images/` 공개 | 개발용 파일·AI 원본 폴더 |
| 생성 실패 메시지, AI 색상 추천 오류 | 예외 원문(서버 경로, `http://ai:5000`, `m_no: M…`)이 화면에 표시 |
| 프론트 번들 | 컨테이너 경로(`/data/acc-front/public`)를 넣어 절대경로를 만들어 보내고, 서버는 그 경로를 믿음 |
| 모든 요청 본문의 `m_no`, 내 정보의 회원번호, JWT 의 회원번호·이메일·이름 | 내부 식별자 노출 |
| 운영 콘솔 로그 | 응답 전체(경로 포함)가 브라우저 콘솔에 남음 |

**해결**
- **파일 주소를 토큰으로**: 백엔드가 모든 API 응답에서 내부 경로(`/data/promotion/…`, AI `/static/…`, `/poster-images/…`, 절대경로)를 `/files/{토큰}.{확장자}` 로 바꾼다(`PublicPathResponseAdvice`). 토큰은 "종류:경로"를 AES-GCM 으로 암호화한 값으로, IV 를 평문 HMAC 으로 만들어 같은 파일은 같은 주소가 되고(캐시·비교 유지), 위조하면 풀리지 않는다(`UrlCipher`).
- **요청은 되돌린다**: 화면이 돌려보내는 `/files/…` 는 백엔드가 원래 웹 경로로 복원한다(`PublicPathRequestAdvice`). 기존 생성 로직·DB 는 바꾸지 않았다. AI 빌드에 필요한 절대경로는 백엔드가 직접 만든다.
- **공개 경로 제거**: nginx `/data/`, `/static/`, 백엔드 `/static/**` 중계, `/poster-images/**` 를 없애고 404 로 응답. 파일은 `/files/{토큰}` 으로만 나간다(토큰이 가리키는 폴더 밖은 거부).
- **남은 내부 정보 지우기**: 응답 문자열 속 내부 호스트 주소·서버 절대경로는 `(내부 서버)`, `(서버 경로)` 로 바꾼다. 작업 실패 사유와 AI 오류는 사용자용 문장으로만 내보내고 원문은 로그에만 남긴다.
- **회원번호**: 요청의 `m_no` 주입 제거, 본인 정보 응답·내 정보 화면에서 제외(관리자 화면만 포함), JWT 에는 암호화한 회원번호만 담는다.
- **기타**: 패키지 파일 이름은 표시용 이름(`메인포스터.png`), 운영 빌드에서 `console.log` 제거, `/testpage` 는 개발 서버에서만, nginx 버전 헤더 제거.
- **같이 고친 버그**: AI 가 모든 회원의 파생물을 `M000001` 폴더에 저장하던 문제. 빌드 요청의 베이스 경로에서 회원 폴더를 읽어 쓴다(`request_member`, 요청별 contextvar).

**검증**: 로그인 없이 예전 경로 4종 모두 404. 주요 응답(템플릿, 진행 상태, 파생물, 내 정보)에 회원번호·`/data/`·`/static/` 0건. `/files/` 이미지 200, 위조 토큰 404. 진행 상태에 토큰을 저장하면 DB 에는 원래 경로로 복원됨.

**후속 정리**
- test 로그인: 백엔드·compose 기본값을 `false` 로. 첫 화면의 "test 계정으로 로그인하기" 버튼도 `/api/auth/config` 를 보고 꺼져 있으면 숨긴다 (로그인 화면은 원래 그렇게 동작).
- CORS: compose 기본은 `PUBLIC_URL` 한 곳만 허용. vite 개발 서버를 붙일 때만 `.env` 의 `CORS_ALLOWED_ORIGIN_PATTERNS` 로 넓힌다.
- 리포트: 기획서 정보가 없을 때 "테스트 축제 / 010-1234-5678" 같은 더미로 만들던 것을 중단하고 안내 문구로 응답. 문의처는 기획서의 `contactInfo` 만 쓰고, 보도자료 하단의 실제 기관명(국립아시아문화전당 홍보협력과)·가짜 담당자는 지웠다. 값이 없으면 칸을 숨기고, AI 에는 연락처·부서를 지어내지 말라고 지시한다. AI 연결 실패 메시지도 사용자용 문장으로.

**교훈**: 내부 식별자를 그대로 URL 로 쓰면 "숨기기"와 "권한"이 둘 다 무너진다. 브라우저에는 서버가 만든, 추측할 수 없는 참조만 준다. DTO 마다 고치기보다 응답·요청 경계 한 곳에서 처리하면 예전에 저장된 데이터까지 같이 가려진다.

## 30. 백엔드가 AI 결과를 공유 볼륨 경로로 직접 읽고 지움 (#21 의 남은 곳)

**증상**: #21 이후에도 포스터·마스코트 결과는 백엔드가 `promotion` 볼륨을 마운트해 `python.base-dir` 경로로 읽고, 옮긴 뒤 지우고, "AI 폴더에 남은 4장 재사용" 을 위해 목록까지 직접 봤다. 두 서버를 다른 PC 로 나누면 동작하지 않는 구조.

**해결**
- AI: 백엔드 전용 `/internal/promotion/{type}` (목록, 받기, 삭제). type·파일명은 영문·숫자·`_-.` 만, `PROMOTION_DIR/{type}` 밖은 거부. AI 는 포트를 열지 않고 nginx·백엔드도 `/internal` 을 중계하지 않는다.
- 백엔드: `AiPromotionFiles` 로 받기 + 원본 삭제(삭제 실패 시 받은 파일 롤백). `/files/` 토큰의 AI 원본 이미지도 AI 에서 받아 전달. `python.base-dir` 제거.
- compose: 백엔드의 `promotion` 볼륨, `PYTHON_BASE_DIR`, 쓰지 않던 `FILES_POSTER_IMAGES_DIR` 제거.

**검증**: AI 내부 API 목록·받기·삭제 200, 삭제 후 404, 잘못된 종류 400·경로 조작 404. 백엔드 컨테이너는 promotion 마운트 없이 기동, 백엔드→`ai:5000/internal` 응답 확인. 외부(5173)에서는 SPA 화면만, 8081 은 401. 백엔드 단위 테스트 6개 통과(URL·받기·404·삭제, 이동·DB 미기록·롤백).

**남은 방향 (설계만)**: 반대로 AI 가 에디터 빌드·영상 생성 때 백엔드가 만든 절대경로(`/data/acc-front/public/...`, `/data/acc/...`)를 공유 볼륨에서 읽는다. 바꾸려면 백엔드가 같은 방식의 내부 파일 API(`/internal/files/{토큰}`)를 열고, 빌드 요청에 경로 대신 그 주소를 넣고, AI 는 받아서 임시 파일로 쓴다(`_resolve_poster_path_from_url` 은 이미 http 주소를 받는다). 결과 저장도 AI 가 front-public 에 직접 쓰지 말고 응답·업로드로 넘긴다. 데모 흐름 회귀 위험이 커서 이번에는 하지 않았다.

**관련 커밋**: acc-ai `e98fbc1`, acc-backend `65d9f60`


## 31. 실패를 200 으로 숨김, 다른 프로젝트의 이미지를 재사용할 수 있음

**배경 (의도)**: 서버가 둘이라 "이미지는 만들어졌는데 응답 중에 통신이 끊기는" 경우를 대비해, 백엔드는 AI 폴더에 남은 결과를 "생성됐지만 저장 실패한 것"으로 보고 재사용했다. 느슨하게 연결하면서 비용을 버리지 않으려는 설계였다.

**문제**
- 포스터 `/create-image` 는 한 장이 실패하면 `image_url: ""` 로 넣거나 빼고 `status: success` 200. 원인은 AI 로그에만 남고, 백엔드는 빈 파일명으로 엉뚱한 곳에서 "파일 없음" 예외.
- 지역 트렌드는 AI 가 200 + 빈 데이터, 백엔드도 예외를 잡아 빈 결과 200 → **크레딧이 환불되지 않음**.
- 재사용 판단이 **회원·프로젝트와 무관하게** `{type}/` 폴더 전체에 4장 이상 있는지였다. A 가 남긴 마스코트가 B 의 프로젝트에 붙을 수 있다.
- 마스코트는 한 장 실패하면 만든 장까지 모두 지웠다 (위 재사용에 섞이지 않게 하려고). 성공한 장의 비용을 버린다.
- 다시 만들기는 고른 이미지의 프로젝트가 아니라 회원의 "가장 최근 프로젝트" 기획서로 AI 를 불렀고(#26 과 같은 유형), 마스코트도 포스터 엔드포인트로 보냈다.

**해결 (의도는 살리고 방법을 바꿈)**
- **요청 폴더**: 백엔드가 `batch = 회원_프로젝트` 를 넘기고, AI 는 `{type}/{batch}/{type}_{순번}_{프롬프트 해시}.png` 에 저장한다. 같은 batch 로 다시 요청하면 **이미 만든 장은 다시 만들지 않는다**. 통신이 끊겨도 다시 시도하면 비용 없이 이어지고, 다른 프로젝트와 섞이지 않는다. 폴더 전체를 훑던 재사용 로직은 삭제.
- **정직한 응답**: 일부라도 실패하면 502 + `{message, failed[{index, style_name, error}], succeeded}`. 성공분은 폴더에 남는다.
- **추적**: 백엔드 `AiFailure` 가 이를 "포스터 4장 중 1장(2번)을 만들지 못했습니다. 다시 시도하면 실패한 장만 다시 만듭니다." 로 바꿔 `generation_job.error` 에 남긴다. 모델 오류 원문은 로그에만 (#27).
- 다시 만들기: 고른 이미지의 프로젝트로, 마스코트는 마스코트 엔드포인트로, 요청마다 새 batch (같은 프롬프트라도 새 그림).
- 지역 트렌드: AI·백엔드 모두 502 → 컨트롤러가 환불.

**검증 (무료, 생성 함수를 가짜로 바꿔 끼움)**: 포스터 2번 장 실패 → 502 `[1]` → 다시 요청하면 그 장만 생성 후 200. 다른 batch 는 비어 있고 잘못된 batch 는 400, 다 옮기면 batch 폴더 삭제. 마스코트 3번 장 실패 → recraft·imagen 재시도 → 502 에 성공 3장 보존 → 다시 요청하면 그 장만. 백엔드 단위 테스트(`AiFailureTest` 등).

**교훈**: "느슨한 연결"은 실패를 숨기는 것이 아니라 **같은 요청을 다시 보내도 안전하게(멱등)** 만드는 것이다. 실패는 실패로 알리고, 다시 시도할 때 이미 한 일을 건너뛰면 된다. 재사용 범위는 요청 단위로 좁혀야 한다.

## 32. 기획서 분석을 백그라운드 작업으로

**증상**: 업로드 후 로딩 화면이 기획서 분석 → 트렌드 → 지역 트렌드 세 요청을 직접 기다렸다(실측 112초). 새로고침하거나 다른 화면으로 가면 결과를 잃었다. 트렌드 둘은 `Promise.all` 이라 지역 트렌드 하나만 실패해도 업로드 화면으로 돌아갔다. 분석 뒤 화면은 "가장 최근 프로젝트"를 다시 조회해 결과를 가져왔다.

**해결**
- `POST /api/project/analyze/jobs`: 요청 안에서 프로젝트를 만들고 작업 번호를 바로 돌려준다(`ANALYZE_PROPOSAL`, 포스터·마스코트와 같은 `generation_job`). 결과 `{pNo, proposal, trend, regionTrend}` 는 작업 result 에.
- 크레딧은 세 단계를 각각 차감. 기획서 분석이 실패하면 전부, 트렌드·지역 트렌드가 실패하면 그 몫만 환불. 지역 트렌드 실패는 작업 실패가 아니다 (나머지 결과로 분석 화면에 들어가고 그 탭에 사유 표시).
- 화면은 주소에 `?job=` 을 남겨 새로고침하거나 오른쪽 아래 알림에서 다시 열어도 이어서 본다.

**검증**: 2023 태화강 국가정원 봄꽃축제 기획서로 화면과 같은 경로(nginx → 백엔드 → AI). 112초 만에 SUCCEEDED, 단계 3개 모두 done, 크레딧 500 → 478(2+10+10). AI 가 아직 뜨기 전에 보낸 첫 요청은 "AI 서버에 연결하지 못했습니다" 로 FAILED 되고 세 몫 모두 환불됨을 확인. 브라우저 화면 동작은 아직 직접 눌러 보지 않았다(빌드만 통과).

## 33. AI 가 백엔드 쪽 파일을 공유 폴더에서 직접 읽고 씀 (#30 의 반대 방향)

**어디서 필요한가**
1. 파생물 만들기 (현수막·버스·카드뉴스·리플렛·굿즈·표지판·로고): 백엔드가 고른 포스터·마스코트의 서버 절대경로를 보내고(`toAbsolutePaths`), AI 는 그 파일을 열어 참조 이미지로 쓰고 결과를 front-public 에 직접 저장한다.
2. 홍보영상: 포스터를 첫 장면으로 읽고 mp4 를 front-public 에 직접 저장한다.
3. 카드뉴스·리플렛의 few-shot 레이아웃 이미지(`M000001/25/poster/`)도 같은 폴더에서 읽는다.

같은 서랍을 같이 쓰며 "세 번째 칸 봐" 라고 말하는 구조라 서버를 나누면 동작하지 않는다.

**해결**: `FILES_MODE` 로 고른다. 기본 `shared` 는 지금과 같다 (운영 영향 없음).
- `http`: AI 는 자기 폴더를 쓰고, 에디터 빌드 디스패처 한 곳에서 베이스 이미지를 백엔드 `GET /internal/files?path=data/promotion/...` 로 받아 오고(없을 때만), 파생물·영상 결과는 `PUT` 으로 올려 보낸다. 16개 모듈은 그대로 두었다.
- 백엔드 `/internal/files`: `data/promotion/` 아래만, `INTERNAL_TOKEN` 이 같아야 하고 비우면 꺼진다. nginx 는 중계하지 않는다.
- **저장 위치**: front 의 public 에 두던 이유는 로컬에서 vite 가 바로 보여 주게 하려던 것인데, #27 이후 브라우저는 `/files/{토큰}` 으로만 받으므로 필요 없다. Docker 에서는 이미 서버 쪽 폴더(`./data/front-public`, front 컨테이너는 마운트하지 않음)라 운영 경로는 바꾸지 않았다(기존 파일 보존). 로컬 기본값만 `../acc-front` → `../data/local`.

**검증 (무료)**: AI 를 `FILES_MODE=http`, 자기 폴더(`/tmp/aiown`)로 띄워 백엔드에서 베이스 이미지(4.8MB)를 받아 오고, 만든 파일을 올린 뒤 백엔드에서 다시 받아 내용 일치. 토큰 없이 403, 경로 조작 400, 외부(5173)에서는 SPA 화면. 기본 shared 모드로 #29·#31 테스트를 다시 돌려 회귀 없음.

**남은 것**: http 모드로 실제 파생물·영상을 끝까지 만들어 보는 검증(유료), AI 쪽 다른 경로 읽기(에디터 AI 색상 추천 등)의 fetch 연결, 서버를 실제로 나눈 compose 예시.
